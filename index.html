WGPU Matching · initialisation DIC

Comparaison du pipeline hiérarchique DeepMatching d’INRIA réimplémenté en WebGPU et de HORG pour initialiser la DIC.

Images

Les images doivent avoir les mêmes dimensions. Le navigateur les convertit en niveaux de gris ; les descripteurs et recherches sont calculés sur le GPU.

Paramètres

La fenêtre DIC règle le support de l’initialisation ; l’échelle racine règle la taille maximale du patch dans la pyramide INRIA (512 px par défaut, comme sa configuration CPU pour les images UHD). Toute la grille de racines à cette échelle est calculée pour que la réciprocité soit globale ; les seeds choisissent les bins affichés et exportés. Le rayon limite le déplacement testé ; 0 signifie une carte complète. Les seeds manuelles sont des centres source en pixels, projetés sur la grille atomique INRIA ; le CSV indique le centre apparié.

La taille racine réduite doit contenir 1, 2, 4, 8… cellules atomiques de 4 px par côté. Le score suit la hiérarchie ; seules les correspondances réciproques sont marquées utilisables. La grille automatique est limitée à 512 seeds ; commencez avec la réduction ×4 et un rayon limité.

HORG calcule sur WebGPU la pyramide DoG, l’orientation dominante, le descripteur 64D et les deux voisins exacts. Le nombre de points-clés comparés est plafonné par image. L’affine locale RANSAC est ajustée en JavaScript ; l’IC-GN et le raffinement sous-pixel de SIFT ne sont pas inclus.

Portée et limites de l’implémentation

Le descripteur pixelwise suit maintenant la configuration CPU par défaut d’INRIA : pré-lissage gaussien, gradient fini, huit projections orientées positives, lissages HOG, sigmoïde, neuvième composante constante, puis average-pooling des descripteurs. Le pré-lissage conserve la précision 8 bits de la référence ; le HOG intermédiaire est calculé en float32 et les descripteurs réduits sont stockés en float16. Les calculs pleine résolution sont découpés en tuiles pour borner la mémoire de travail.

Le matching suit les étapes CPU INRIA : patchs atomiques HOG L2-normalisés, cartes de corrélation locales, max-pooling 3×3 et sous-échantillonnage 2, convolution sparse pondérée des quatre enfants, offsets par carte, correction des bords de l’agrégation, puissance 1,4, parcours descendant d’argmax 3×3, accumulation des scores et intersection réciproque. Le HOG et les cartes de réponse sont calculés sur WebGPU.

Le mode de comparaison évalue toutes les racines de la grille INRIA à l’échelle sélectionnée, agrège globalement les meilleurs candidats source et cible, puis applique l’intersection réciproque. La grille par défaut est non chevauchante, avec un pas égal à la taille de la racine, comme dans la configuration CPU d’INRIA. Les seeds servent à extraire les bins demandés du champ calculé. Les variantes d’échelle et de rotation ainsi qu’EpicFlow ne sont pas inclus.

Les centres manuels sont projetés sur la grille atomique source INRIA, de pas 4 pixels après réduction. La sortie reste quantifiée à cette grille, comme dans le code CPU. Les patchs cibles incomplets au bord sont écartés ; la rectification `rectify_conv` des cartes atomiques n’est pas encore portée. Aucun seuil de score ou de marge n’est appliqué : le critère usable est l’intersection réciproque globale sur les racines calculées.
